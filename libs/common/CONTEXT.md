# Game Runtime

The Game Runtime initializes and executes the finite state machine representing a Game Title’s rules. It processes Actions deterministically to advance the Game State of a Game Instance.

## State machine

**Game State Machine**:
The finite state machine representing a Game Title’s rules. Its Machine States and transitions govern how Actions advance play.

**Machine State**:
One state within a Game State Machine. Game State records which Machine State the machine currently occupies.
_Avoid_: Game State, procedural step

**Machine State Handler**:
The rules associated with one Machine State: its permitted Actions, entry behavior, and transitions following Processed Actions.

**Machine State Transition**:
The transition triggered by processing an Action. It may return to the same Machine State, whose entry behavior runs again.
_Avoid_: Game State change

**Machine State Entry**:
Behavior performed upon entering a Machine State. It may change Game State or generate System Actions; initial entry occurs during Game Initialization without an Action-triggered transition.

**Terminal Machine State**:
A Machine State from which no further Actions or transitions are permitted. A specific game determines its result upon entry into this state.

## Game state

**Game State**:
The complete current condition of play needed by the Game State Machine, including its current Machine State.
_Avoid_: Rules State, Machine State

**Game Initialization**:
Creation of the initial Game State followed by entry into the Game State Machine’s initial Machine State.

**Player State**:
The portion of Game State associated with a Player.

**Active Player**:
A Player to whom an Action may currently be attributed under the Game State Machine. Multiple Players may be active simultaneously.

## Actions

**Action**:
A discrete game operation represented by the same model throughout its processing lifecycle. Processing an Action necessarily triggers a Machine State Transition.

**Unprocessed Action**:
An Action that has not yet been accepted and applied. It may still be rejected.

**Processed Action**:
An Action that has been accepted, applied to Game State, triggered its Machine State Transition, and been recorded in history.

**User Action**:
An Action initiated directly through user input. User describes its origin, not whether it is attributed to a Player.

**System Action**:
An Action generated by the Game State Machine as an automatic rules consequence. It is processed and recorded as a first-class Action.

**Player Action**:
An Action attributed to a particular Player, regardless of whether its origin is User or System.

**Simultaneous Action Group**:
A set of Actions that participants may prepare independently from the same starting Game State. A member may remain valid after other members have been processed, but not after an unrelated Action.

**Information-Revealing Action**:
A Processed Action whose result gives a participant knowledge that could influence an earlier choice. User undo cannot cross it without compromising the game.

**Action Reversal**:
Mechanical restoration of Game State to immediately before one Processed Action. It is one part of the broader cross-context Undo operation.

## Execution

**Deterministic Execution**:
The guarantee that the same initial Game State and ordered Processed Actions produce the same resulting Game State and System Action cascade in every Game Runtime.
