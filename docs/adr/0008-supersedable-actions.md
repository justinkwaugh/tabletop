# Supersedable Actions replace a standing declaration in place

A Game Title may declare an Action type as supersedable by requiring the literal `supersedable: true` in its registered Action schema. A new Action of that type may name, in `supersedesActionId`, the Processed Action it replaces: the same Player's earlier User Action of the same type. The replacement is honoured only when the named Action's state manipulation was entirely self-contained, which the host or Local Game establishes by replay: it reverses history back through the named Action, re-executes every later User Action, requires each regenerated cascade to match the recorded one, and requires the replacement to apply on the result. If any step differs, a later Action depended on the named one and the replacement is rejected. An unnamed Action of a supersedable type is also rejected while a same-player Action of that type stands at the tail, so a supersedable type can never accumulate more than one unconsumed record per Player.

Persisting a replacement reuses Action Reversal and the redo path that Undo already has, so history is rewritten once and other clients receive one reversal and one addition. The mechanism is independent of Out-of-Turn Actions; the stock-round standing instruction is both, but a turn-taking declaration could be supersedable alone.
