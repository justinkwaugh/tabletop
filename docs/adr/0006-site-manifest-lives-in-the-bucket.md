# The Site Manifest lives in the bucket, not the repository

The Site Manifest, which records the current Publication of every Game Title and the current Site Frontend Artifact, is stored only in the static bucket and changed only by the deploy tool. The repository keeps a Game Catalogue of title and package identifiers, and package versions carry the release identity through `package.json` and per-artifact git tags. Keeping a manifest copy in the repository meant a commit could claim versions that production did not serve, and every deploy had to reconcile the two; with the bucket as the single record, a deploy reads the current manifest, backs it up, rewrites only the artifacts it published, and invalidates the backend cache, so the serving state is always what the last successful deploy left. The cost is that a fresh checkout cannot tell what production serves without asking the bucket or the backend, and local development derives its manifest from the catalogue and package versions instead of reading a file.
